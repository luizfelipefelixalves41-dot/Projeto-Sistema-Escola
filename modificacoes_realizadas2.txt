MODIFICACOES REALIZADAS NO SISTEMA ACADEMICO

Este arquivo registra as principais alteracoes feitas no projeto Sistema
Academico, incluindo as melhorias anteriores e as melhorias finais aplicadas na
versao web.

1. Evolucao geral do projeto

- O projeto evoluiu de uma base em orientacao a objetos para uma aplicacao web
  com Flask.
- Foram mantidas as classes principais do modelo academico:
  Pessoa, Aluno, Professor, Disciplina e SistemaAcademico.
- A aplicacao passou a ter interface no navegador, banco de dados, relatorios,
  validacoes e testes automatizados.

2. Tela de entrada do sistema

- Foi criada uma nova tela inicial em /.
- A tela apresenta a mensagem "Bem-vindo ao site escolar".
- Foram adicionados atalhos para entrar nas areas de alunos, professores,
  disciplinas, matriculas, painel e relatorios.
- O painel principal, que antes ficava na rota /, foi movido para /painel.
- O menu superior recebeu o link "Painel".

Arquivos relacionados:

- app.py
- templates/entrada.html
- templates/base.html
- static/styles.css

3. Painel principal

- O painel mostra um resumo geral com:
  - alunos ativos;
  - professores ativos;
  - disciplinas ativas;
  - matriculas ativas.
- A listagem do painel passou a exibir apenas disciplinas ativas.
- O painel continua permitindo acesso aos relatorios JSON e PDF.

Arquivos relacionados:

- app.py
- templates/index.html

4. Melhorias de validacao

- Foram adicionadas validacoes no backend para campos obrigatorios.
- A carga horaria passou a ser validada como numero inteiro positivo.
- O sistema passou a verificar se aluno, professor e disciplina existem antes
  de salvar vinculos.
- A validacao de CPF foi melhorada.
- Antes o sistema apenas conferia se o CPF tinha 11 digitos.
- Agora o CPF e validado pelos digitos verificadores.
- CPFs invalidos, como 111.111.111-11, passaram a ser recusados.
- Foi criado o arquivo validators.py para concentrar regras de validacao.

Arquivos relacionados:

- app.py
- validators.py

5. Melhorias contra duplicidade

- O sistema continua usando restricoes UNIQUE no banco de dados.
- Foram melhoradas as mensagens para CPF, matricula, registro ou codigo ja
  cadastrados.
- O cadastro de aluno, professor e disciplina trata erros de integridade de
  forma mais clara.
- A matricula duplicada continua bloqueada.
- Se uma matricula removida for cadastrada novamente, ela pode ser reativada.

Arquivos relacionados:

- app.py
- schema.sql
- db.py

6. Arquivamento e remocao logica

- A remocao de matricula continua sendo logica.
- A matricula deixa de aparecer como ativa, mas permanece no banco de dados.
- Foram adicionados campos de controle para arquivamento:
  - ativo;
  - arquivado_em.
- Alunos, professores e disciplinas passaram a ter arquivamento logico.
- Ao arquivar um aluno, suas matriculas ativas sao desativadas.
- Ao arquivar uma disciplina, suas matriculas ativas sao desativadas.
- Ao arquivar um professor, suas disciplinas ficam sem professor definido.
- Essa abordagem preserva historico e evita perda definitiva de dados.

Arquivos relacionados:

- app.py
- db.py
- schema.sql
- Aluno.py

7. Banco de dados

- O sistema tenta usar MySQL como banco principal.
- Se o MySQL nao estiver disponivel, usa SQLite local automaticamente.
- O banco SQLite local usa o arquivo sistema_academico.sqlite3.
- O db.py foi melhorado para garantir o schema do SQLite.
- O db.py tambem passou a tentar adaptar tabelas MySQL antigas, adicionando as
  colunas ativo e arquivado_em quando necessario.
- O schema.sql foi atualizado para incluir as novas colunas.

Arquivos relacionados:

- db.py
- schema.sql
- sistema_academico.sqlite3

11. Testes automatizados

- Foi criada a pasta tests.
- Foi criado o arquivo tests/test_app.py.
- Os testes usam unittest, sem dependencia extra.
- Foram testados:
  - CPF valido;
  - CPF invalido;
  - bloqueio de aluno duplicado;
  - arquivamento de aluno;
  - desativacao de matriculas ao arquivar aluno.
- Os testes foram executados com:

  python -m unittest discover -s tests

- Resultado obtido:

  Ran 4 tests
  OK

Arquivos relacionados:

- tests/test_app.py
- validators.py
- app.py
